The Algorithms

Every algorithm has a runnable Python file, written notes and its own animation. The stripe on each card marks the worst-case class: amber for quadratic, blue for log-linear, green for the linear-time non-comparison sorts.

Bubble Sort

O(n²) worst · O(n) best

Repeatedly swaps adjacent elements that are out of order. The early-exit flag makes it genuinely fast on sorted input.

Insertion Sort

O(n²) worst · O(n) best

Grows a sorted prefix one element at a time. Excellent on small or nearly sorted data, and the basis of several hybrid sorts.

Stable In-place Adaptive

Selection Sort

O(n²) always

Finds the smallest remaining element and swaps it into place. Makes the fewest writes of any quadratic sort: exactly n−1.

Not stable In-place Not adaptive

Shell Sort

O(n²) worst · gap-dependent

Insertion sort over progressively smaller gaps, so distant elements move a long way early. Performance hinges entirely on the gap sequence.

Not stable In-place Adaptive

Merge Sort

O(n log n) always

Splits the array in half, sorts each side, then merges. Its running time never degrades, which is why it is the safe choice for worst-case guarantees.

Stable Not in-place Not adaptive
Notes Code Visualize →

Quick Sort

O(n log n) average · O(n²) worst

Partitions around a randomly chosen pivot and recurses. Usually the fastest comparison sort in practice thanks to its tight inner loop and cache behaviour.

Not stable In-place Not adaptive

Heap Sort

O(n log n) always

Builds a max-heap, then repeatedly moves the root to the end. Merge Sort's worst-case guarantee with Quick Sort's O(1) memory.

Not stable In-place Not adaptive

Tim Sort

O(n log n) worst · O(n) best

Finds naturally ordered runs and merges them, falling back to insertion sort on short ones. This is the algorithm behind Python's own sorted().

Stable Not in-place Adaptive

Counting Sort

O(n + k) · integers only

Tallies how often each value occurs instead of comparing elements, which is how it beats the O(n log n) barrier. Needs a narrow value range.

Stable Not in-place Not comparison-based
Notes Code Visualize →

Radix Sort

O(d × (n + b)) · integers only

Runs a stable counting sort on one digit at a time, least significant first. Earlier passes survive later ones precisely because each pass is stable.

Stable Not in-place Not comparison-based

Bucket Sort

O(n + k) average · O(n²) worst

Scatters values into ordered buckets, sorts each one, then concatenates. Fast on evenly spread data, poor on skewed data.
